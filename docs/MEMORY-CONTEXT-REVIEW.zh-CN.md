# 记忆、全局偏好与性格改进评估

调研及验证日期：2026-10-27。对应 v0.3.0 改动；运行时目标为 Windows Desktop bundled 0.2.1-rc.3。本文区分外部设计依据、实现选择与实测结果。

## 官方资料调研

| 项目 | 官方公开设计 | 对本插件的启发 |
| --- | --- | --- |
| [Claude Code memory](https://code.claude.com/docs/en/memory) | 用户/项目指令与自动记忆分开；自动记忆使用本地目录、短索引和主题文件，索引有启动加载上限，详情按需读取 | 长期保存不等于全部常驻；紧凑预览与全文按需读取 |
| [Cursor Rules](https://cursor.com/docs/rules) | 用户规则跨项目，项目规则保存在项目目录；规则引用文件可以按需读取 | 全局个人偏好和项目事实需要明确的不同范围 |
| [Letta memory blocks](https://docs.letta.com/v1-sdk/memory/memory-blocks) / [context hierarchy](https://docs.letta.com/v1-sdk/memory/context-hierarchy) | 有字符上限的常驻记忆块，用户与 persona 可以分开；更大或不常用的内容置于外部检索层 | 性格只带有效状态，核心偏好保持小体积，其余内容检索 |
| [LangGraph memory](https://docs.langchain.com/oss/python/concepts/memory) | 区分线程历史与跨线程长期记忆；长期记录使用 namespace/key 组织 JSON 数据 | `global` 与工作区是存储范围；会话上下文寿命应独立管理 |

上述资料说明常见架构选择，并不证明某一种检索或人格算法适用于所有模型。Cursor 的旧 Memories URL 当前重定向到文档首页，未据旧搜索摘要断言其现行自动记忆审批机制。

## 对原改进建议的判断

1. **分页与工具预算：必要且优先级高。** 原 `brain_list` 可以输出整个可见库，单次自动注入的 6000 字符限制无法约束它。增加 `brain_read` 后，预览截短不会让完整记忆不可达。
2. **精简性格字段：合理但不够。** 证据计数、控制代数与版本属于管理界面，模型只需要有效模式和维度。删除这些字段能减少无意义变化，但不能独自解决动态参考快照累积。
3. **管理旧快照：需要宿主级验证。** 不能靠“新快照覆盖旧快照”的文字说明减少 token。本实现使用宿主已有的持久化单节点替换协议，保留事件原文，改变模型可见表面；不会直接修改冻结消息或接管其他插件的上下文。
4. **Token 预算：有用，但必须如实称为估算。** 本插件不绑定某个提供方 tokenizer，也无法给整段会话预留精确剩余窗口。新增估算限额与硬字符限额同时生效；这是局部保护，不是精确计费或不会超窗的保证。
5. **没有引入向量数据库。** 默认上限 500 条、单条最多 2000 字符，现有 JSON 原子写入、范围隔离和关键词检索仍能满足当前规模。向量服务会增加模型、网络及部署依赖，也不能替代预算和范围管理；当前没有足够证据需要它。

## 最终实现

### 存储与全局记忆

- 保持 `schemaVersion=1`、默认路径、原子替换、并发锁、删除标记、导入合并及原有人工控制，不对用户已有库做迁移写入。
- `global` 在同一 `DSH_HOME` / `dataDir` 的会话和工作区间共享。不同目录、用户及设备不自动同步。
- 自动提取根据完整证据所在句子判别项目限定，避免模型只摘取偏好片段时把项目偏好扩大成全局偏好。明确个人偏好可归入 global；无法识别的语义仍依赖提取器及人工纠正。
- 先选最多 3 条全局 preference/instruction，数量还受总条数预算约三分之一的限制；与问题无关的核心偏好有约三分之一的估算 Token 子预算。随后按关键词检索可见全局及当前工作区记录。
- 常驻预览最多 400 个 Unicode 码点，带 ID 与范围；全文留在本地。没有把全部 global 记录都当成常驻指令。

### 模型上下文与查询工具

- 在 `agent/request` 阶段维护独立的 `brain:long-term-reference` 用户参考消息，当前指令优先，不经过模板插值。内容不变时不写新事件；内容变化时只替换自己的一个模型可见节点。
- 替换前使用宿主 `tokenMeter.estimateMessage` 写入相邻的 `compaction/prune` 计量事件，避免模型输入已缩短但客户端统计仍按旧消息计算。
- 压缩移除当前参考节点后，下次请求重新生成。关闭注入时用简短禁用标记清除旧参考。旧版混合 runtime 快照只移除 Brain 命名分节；原始事件与其他分节保留。
- 自动参考默认上限：6000 UTF-16 字符、2000 估算 tokens、10 条预览。预算不足以放入完整风格说明时可继续提供其他能容纳的参考，不再直接关闭全部内容。
- `brain_list` / `brain_search` 返回 `{records,total,nextCursor}`，默认最多 10 条、可设 1..20；每条最多 400 码点预览。`brain_read` 返回 `{id,scope,text,nextCursor}`，按 Unicode 安全边界分段，拼接可恢复原文。
- 工具结果默认同样受 6000 字符和 2000 估算 tokens 限制。计量针对实际序列化 JSON，包括转义和游标。`brain_remember` 只返回保存确认与 ID，不重复输出长正文。
- 游标绑定可见结果的内容版本、查询类型、查询内容、范围及工作区。结果内容或顺序变化后要求重新读取，普通聊天计数和单独性格更新不会中断分页，不能用旧游标越过范围或悄悄漏掉更新。
- CLI 的 list/export 及面向用户的管理命令保留完整数据访问。`/brain status` 显示预算和本插件进程最近一次生成的参考内容用量，不声称它是当前聊天的总消耗。

### 性格稳定性

原算法达到三次反馈门槛后持续取历史均值，旧反馈可能在收到一次相反反馈后仍推动性格继续往旧方向变化。新算法使用最近最多 5 次有效反馈：

1. 至少 3 次、且至少 75% 支持相对当前值的同一变化方向。
2. 最新反馈必须支持该方向；否则不更新。
3. 目标为支持反馈的中位数，每次移动不超过 0.05。
4. 当前值距离反馈不超过 0.05 时不微调，避免细小数值噪声。
5. 已由本地规则识别的明确表达使用确定目标值，避免提取模型给同一句话轻微不同的数值。

已有去重、逐字证据、临时/引用排除、冻结、manual/off、控制代数、重置与回退继续生效。项目限定的风格请求保存成工作区偏好，不训练全局性格。统计、版本、原始证据和历史不进入自动风格参考。

这些门槛是本项目的保守产品选择，并不是文献证明的最优参数。稳定指状态不会被无关或矛盾反馈轻易推动，并能持久恢复；实际模型的语气仍受当前任务、系统指令和模型能力影响。需要精确固定维度时用 manual 或 freeze。

## 实测与反例验证

- 500 条接近单条上限的合成记忆：遍历分页可取到全部 500 个不同 ID；每页和自动参考同时满足字符、估算 Token 限额。包含中文、emoji、反斜线和引号，按页读取可精确还原正文。
- 最小工具预算 512 字符 / 128 估算 tokens：依然能返回一条缩短预览并前进；不同查询、工作区、范围和修改后的旧游标拒绝继续。
- 重启后跨 A/B 两个工作区以及无工作区会话召回 global 偏好；无关问题仍携带少量核心偏好。工作区私有 ID 的全文读取在另一工作区失败。
- 性格证据前两轮只增加证据，模型参考逐字不变；连续一致反馈在门槛后有界收敛。24 次交替相反反馈保持中性；单次反向反馈不会延续旧方向；普通聊天、临时及项目反馈不改变全局状态。
- 真实 Desktop 0.2.1-rc.3 服务与合成 provider：连续 30 轮每次只有 1 个当前 Brain 快照，样本中的最大参考内容为 774 字符；验证 cwd 切换、旧共享快照迁移、其他分节保留、会话重放、压缩后恢复、关闭后清除、宿主 token 统计一致。
- 原生设置服务验证 23 个字段、保存/volatile 更新、重启恢复与已有风格保留；客户端表单边界测试继续覆盖 schema 派生字段。随后在日常 Desktop 原生页面确认新增字段显示与组件运行。

完整命令结果及适用范围见[验证记录](VALIDATION.zh-CN.md)。自动化测试使用临时合成目录。随后在日常 Desktop 以 DeepSeek-V4.1-Flash 进行两个新会话的真实工具调用验收：全局合成记录写入、全文读取、跨会话搜索召回和清理后复核通过；原有记忆与性格内容、配置均保留。没有读取既有聊天历史或凭据内容。

## 合理性结论与取舍

本改动解决了已复现的自动快照累积和无界工具输出，并提升全局偏好可用性及风格状态稳定性。保持本地结构化存储和无新增 npm 依赖，与当前规模相称。

代价与限制必须保留：替换较早模型消息会改变前缀，可能降低 provider 缓存命中率；单个参考消息有界不代表整段聊天有界，历史工具结果、用户原话、助手复述或压缩摘要中的记忆副本仍受宿主管理。删除长期记忆不等于擦除所有既有对话。磁盘审计历史会继续增长。跨版本宿主兼容性、真实网络模型的长期风格遵循率和其他平台原生 UI 表现需要独立验证。
