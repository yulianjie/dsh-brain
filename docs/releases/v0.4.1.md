# DSH Brain v0.4.1

本版本修复两个 Windows 并发场景下偶发的写入失败：`.brain.lock` 目录争用时 NTFS 把 `EEXIST` 误报成 `EPERM`/`EBUSY` 导致普通写入直接失败，以及 `brain.json` 被读取方短暂占用时最终改名替换报 `EPERM` 造成写丢失。两项修复都只影响 Windows；其他平台行为与 0.4.0 相同。从本版本起发布改由 GitHub Actions 自动完成。

## 主要变化

### 锁目录争用按争用处理

- 并发写入者同时创建或移除 `.brain.lock` 时，NTFS 可能把目录操作报成 `EPERM`/`EBUSY` 而不是 `EEXIST`，此前这会让一次普通写入直接失败。这些错误码现在并入原有的有界等待；只有创建锁目录才算争用，写 `owner.json` 失败仍然立即报错。
- 解锁改用 `fs.rm` 的有界重试（`maxRetries`/`retryDelay`）；锁目录已消失视为解锁成功。接管目录清理失败不再中止触发回收的那次写入。
- 等待超时报错保留原始 errno `code`（`error.code === 'EPERM'`）并以 `cause` 指向最初失败；只有锁目录从未出现时才提示 "cannot be created"，已存在的目录仍报 "locked"。
- 争用只根据最近一次失败判断，旧的 `EPERM` 不会污染后续的 `EEXIST` 等待。新增回归测试覆盖 `EPERM`、`EBUSY` 与争用重置。

### store 改名替换带重试

- Windows 上另一个句柄打开 `brain.json` 时（`list`、`search`、`personality`、`stats`、每次提示词都会调用的 `context()`，或 `personalityGeneration` 读取器），最终的改名替换会报 `EPERM`：CLI 写入可能失败，后台学习写入也可能在与 `context()` 读取重叠时失败。
- `Brain._write` 现在对该改名在 Windows 上按 `EPERM`/`EACCES`/`EBUSY` 以 1–5 ms 退避重试至多 5 秒，仍在存储锁内，仍响应 abort 信号并清理临时文件。一直不消失的失败（例如只读的 `brain.json`）在 5 秒后浮现原始错误，存储保持原样。其他平台与其他错误码不变。

### 自动发布

- 推送 `v<版本>` tag 会触发 GitHub Actions 自动执行同一套 `npm run verify`，单一 `npm pack` 出包并生成 `SHA256SUMS.txt`，把同一份 tarball 同时发布到 GitHub Release 和 npm，发布后回读 registry 比对校验和。手工发布清单仍保留在[发布检查清单](../RELEASING.md)。

## 兼容性与升级

- 包名仍为 `@yulianjie/dsh-brain`，`id: brain`、默认存储路径和 schemaVersion=1 不变。升级保留已有记忆、风格、历史和配置。
- 两项行为修复仅在 Windows 生效；Linux 与 macOS 与 0.4.0 相同。
- 锁文件格式与 0.4.0 一致（含 `host` 字段与同机接管行为）。
- 命令、六个模型工具和 23 项原生设置不变。
- Desktop 集成目标仍为 **Windows bundled runtime 0.2.1-rc.3**；Node 核心和 CLI 要求 Node 22+。

## 安装

```powershell
$dshCli = Join-Path $env:LOCALAPPDATA 'Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd'
& $dshCli plugin --profile desktop add '@yulianjie/dsh-brain@0.4.1'
```

或下载附件 `yulianjie-dsh-brain-0.4.1.tgz` 与 `SHA256SUMS.txt`，核对校验值后执行：

```powershell
$expected = ((Get-Content .\SHA256SUMS.txt -Raw).Trim() -split '\s+')[0]
if ((Get-FileHash .\yulianjie-dsh-brain-0.4.1.tgz -Algorithm SHA256).Hash -ne $expected) { throw 'SHA256 mismatch' }
& $dshCli plugin --profile desktop add (Resolve-Path .\yulianjie-dsh-brain-0.4.1.tgz).Path
```

正常退出并重新启动 Desktop，在插件页面确认组件运行，再执行 `/brain status`。
